## 1. 專題介紹（Project Overview）

本專題使用 STM32 微控制器製作智慧藥盒提醒系統，透過 LED 燈號、按鈕及計時器，模擬日常生活中的服藥提醒功能。

系統設計早餐與晚餐兩個服藥時段，利用 Timer 自動判斷提醒時間，並根據使用者是否按下確認按鈕，切換不同的服藥狀態。

當使用者未在指定時間內確認服藥時，系統會進入逾時提醒狀態，最後記錄為漏服（MISSED），並自動進入下一個服藥時段。

本專題主要整合 GPIO、Timer、外部中斷（EXTI）、UART 及有限狀態機（FSM）等微控制器應用技術。

## 2. 專題動機（Motivation）

日常生活中，長者或需要定期服藥的人，可能因忙碌或健忘而錯過服藥時間。

因此，希望利用 STM32 開發一套簡單的智慧藥盒原型，透過不同顏色的 LED 提醒使用者服藥，並使用按鈕確認服藥狀態。

除了提醒功能，也希望系統能夠自動判斷逾時與漏服情況，減少使用者必須手動操作的步驟。

## 4. 系統功能（Features）

### 4.1 定時提醒（Scheduled Reminder）

系統利用 TIM2 提供計時基準，模擬早餐與晚餐的服藥時間。

| 系統時間 | 功能 |
|---|---|
| 0 秒 | 系統初始化，進入等待狀態 |
| 15 秒 | 早餐服藥提醒 |
| 25 秒 | 早餐未確認時進入逾時提醒 |
| 30 秒 | 早餐提醒結束，未確認則記錄 MISSED |
| 40 秒 | 晚餐服藥提醒 |
| 50 秒 | 晚餐未確認時進入逾時提醒 |
| 55 秒 | 晚餐提醒結束，未確認則記錄 MISSED |
| 60 秒 | 當日流程結束 |

上述時間為專題展示使用的模擬時間，並非實際生活中的服藥時刻。

### 4.2 LED 狀態顯示（LED Indication）

系統透過三種顏色的 LED 顯示服藥狀態。

| LED | 狀態 | 功能 |
|---|---|---|
| 黃燈 | REMINDING | 提醒使用者服藥 |
| 綠燈 | CONFIRMED | 表示已確認服藥 |
| 紅燈 | OVERDUE | 表示已超過提醒時間 |
| 燈號結束 | MISSED | 該時段未確認服藥，完成漏服紀錄 |

### 4.3 按鈕確認（Button Confirmation）

使用 STM32 NUCLEO-G474RE 開發板上的 B1 按鈕作為服藥確認輸入。

當使用者在允許的時間內按下按鈕，系統會更新對應時段的服藥狀態，並以綠色 LED 顯示確認結果。

按鈕事件透過外部中斷處理，並加入防彈跳判斷，避免單次按壓造成重複觸發。

### 4.4 自動切換服藥時段

系統分別記錄早餐與晚餐的服藥狀態。

即使使用者沒有按下確認按鈕，系統仍會依照預設時間自動進入下一個服藥時段。

完成晚餐流程後，系統結束當日提醒，避免持續停留在逾時警示狀態。

### 4.5 UART 資訊輸出

程式設計使用 LPUART1 輸出系統狀態訊息，方便透過串列通訊工具觀察系統執行過程。

UART 可用於輔助除錯及檢查服藥狀態切換。

**測試註記：** UART 實際輸出結果須以串列監控工具的測試畫面確認。

```text

    v                      |

    |                      |
    +---- 按下 B1 ---------+
    |                      |
    v                      v

    |                      |
```

系統透過 Timer 自動推進流程，不需要使用者手動切換早餐與晚餐。

## 6. 使用技術（Technical Implementation）

### 6.1 GPIO

使用 GPIO 控制外部 LED，並透過按鈕輸入取得使用者的確認操作。

### 6.2 Timer Interrupt

使用 TIM2 產生週期性中斷，建立系統計時基準。

程式透過 `system_ms` 記錄經過時間，作為提醒、逾時與結束流程的判斷依據。

### 6.3 External Interrupt（EXTI）

使用 PC13 的外部中斷偵測 B1 按鈕事件。

透過中斷方式處理按鈕輸入，不需要在主迴圈持續等待按鈕按下。

### 6.4 Non-blocking

系統使用時間比較與狀態判斷管理提醒流程，避免使用長時間的 `HAL_Delay()` 阻塞主要控制邏輯。

因此，系統可以持續檢查時間與處理按鈕事件。

### 6.5 Debounce

按鈕加入軟體防彈跳機制，利用時間間隔判斷，減少機械按鈕造成的重複觸發。

### 6.6 Finite State Machine（FSM）

系統使用有限狀態機管理不同服藥階段。

| 狀態 | 說明 |
|---|---|
| WAITING | 等待提醒時間 |
| REMINDING | 進入服藥提醒 |
| CONFIRMED | 已確認服藥 |
| OVERDUE | 超過提醒時間 |
| MISSED | 該時段未確認服藥 |

早餐與晚餐分別使用獨立狀態變數管理。

### 6.7 UART

使用 LPUART1 傳送系統狀態資訊，協助觀察程式執行與除錯。
